### 5.1 腾娱 · QPilot Code · 全栈 · 2026.03–至今

**是什么：** 企业内部的 AI 编程平台。用户用自然语言描述需求，Agent 在云端沙箱里写代码、启动预览、提交 Git，最后部署成可访问的应用。仓库 2025-11 由其他同事创建，我 2026-03 加入。

**团队和我的位置：** 2026-03 以后主要是我和 albertmo 两个人在写，平级，按模块分工。不重复计算合并提交的话，我在后端提交 208 次、前端 166 次，约占四成；对方后端 358 次、前端 247 次。其他人零星提交。

**技术栈：** TypeScript、Node.js、Express、React、OpenSandbox SDK、Claude Agent SDK、DeepAgents、OpenAI Agents SDK（已收口）、MCP、PostgreSQL、腾讯云 COS、TKE、Docker、伽利略监控、Orange CI。

**我负责的模块（方案、实现、上线都由我完成）：**

1. **沙箱 Git 集成**
   - 做了冲突处理（含 AI 辅助解决冲突）、按需 AI 生成提交信息、推送前预检和远程领先预警。
   - 清理预览产生的临时文件，修正 untracked 文件触发的假冲突。
   - 受控写入：模型不再在沙箱里直接 push。后端签发 30 分钟有效、带签名和载荷哈希的令牌，模型只能拿令牌调后端接口，后端先做冲突和分叉检查。工蜂凭证不进沙箱。
   - 沙箱从 e2b 换成 OpenSandbox 后，每条命令都是一次独立往返。我把同一接口要跑的命令合成一段脚本，7 个 Git 接口都降到一次往返：状态检查从十多次降到 1 次，提交推送 6→1，拉取前检查 5→1，与远程 diff 4→1，分支列表 4→1。
2. **预览启动与状态判断**
   - 失败进程一直占着 3000 端口，下一轮服务就改用别的端口，后端却还在检查 3000。改成启动前和失败时都清理目标端口；日志已经出现致命错误时提前结束健康检查。缺文件这个复现场景从约 60 秒降到约 6 秒。
   - 端口扫描把模型访问网关的出站连接误判成端口被占：改成只查处于 LISTEN 状态的端口。
   - 沙箱回收后，预览误判成没有项目而不启动：改为同时读版本快照。
   - 重试时状态在启动中和失败之间来回跳：用本轮的启动时间区分旧失败和这一轮的失败。
   - 导入 Git 项目后预览启动失败会无限重试：已修复。
   - 启动失败时，给非开发者展示一句看得懂的错误摘要。
3. **部署链路**
   - 部署代理丢 POST body：FastAPI 返回 422、Express 拿到 body=null，已修复。
   - 部署到子域名后白屏：部署时强制把 vite base 改成 `/`。
   - 老部署代理失败时，提示用户重新部署。
   - 白名单用户可自定义 Pod 内存。
   - 部署前做存储预检：只有数据会随容器丢失时，才弹确认框并说明原因。
   - deploy-preflight 原来由模型手写 curl 调接口，改成接入受控的部署 MCP 工具，令牌和本次操作绑定。
   - 部署成功时记录来源版本，版本历史能显示哪些版本已发布。
4. **上传与身份**
   - 用户项目统一上传 API，单文件上限 1GB；聊天附件统一转存 COS。
   - 上传门禁改成按 Origin 域名白名单校验，并放在解析请求体之前。
   - 写了《平台上传统一到 COS 规划》。
   - 接入太湖 TOF 统一认证，让预览和部署用同一套身份方案，密钥不进沙箱。
   - `/auth/me` 返回员工完整信息；维护 oa skill，供生成的应用获取登录态。
   - 写了 TOF 身份统一、auth/me 员工信息整合、平台域名收归三份方案文档。
5. **Skills 与 Agent 运行时**
   - 重构 DeepAgents 的沙箱外 Skills：内置 Skills 原来没有同步进沙箱，现在会同步，并改用 SDK 原生的渐进式加载，去掉手工往提示词里塞 Skills 列表。
   - 接入官方 Skills，做了 Skill 详情页。
   - 后端负责会话链路统一收口到 Claude sandbox chat（OpenAI Agents SDK 和 DeepAgents 的会话都改走 Claude Agent SDK，并保持对旧数据的兼容）。
   - 默认全栈模板从 react-express 换成 python-static。
   - 新增提示词增强接口。
6. **会话与协作**
   - 消息截断接口，支持编辑后重发，并同步清理模型侧的会话上下文。
   - 对话输入队列：模型输出期间可以继续输入，前后端都做了，队列持久化。
   - 历史会话按需迁移：多线程模型上线前的老项目打开是空白，方案文档里统计约 3507 个会话受影响。新增迁移接口，后端返回需要迁移的信号，前端据此迁移一次；只读协作者也能看到历史对话。
   - 项目管理员的设置和转让，处理并发和校验。
   - 项目列表改按会话维度查询，支持置顶和按权限分 Tab。
7. **监控**
   - 部署、Git 提交和推送、首页核心接口接入伽利略结构化上报（P0/P1）。
   - 部署代理的日志降噪。
8. **前端工作台**
   - 首页项目列表、工蜂仓库导入（多实例下导入卡片卡住、文件树空白都已修复）、部署前确认框、复制 LLM 输出。
   - 统一会话页 URL。
