## 题目 1：Agent Harness（主题 1.0）

### 问 1：什么是 Agent Harness？和 Agent Framework、MCP 是不是一回事？

**答（要点）**：harness 是一种规范模型使用的方法；模型本质是算下一个字的机器，要让它处理日常工作还需要记忆、上下文、可调用的工具，才能接触到工作内容并按一定方法运行。MCP 是第三方提供给 AI 调用的能力接口，类似第三方接口，只是调用方是 AI。Agent Framework 不了解。

**评价**：✅「模型本质是算下一个字的机器」这个直觉准；抓到了上下文/记忆/工具是关键。⚠️ harness 说成「方法」太虚；MCP 定位不准；framework 空白。

**引导轮 1**（提示：谁执行/谁校验工具调用、MCP 定的是能力还是格式、SDK 是谁的循环）
**答**：MCP 是一种规范，按这个规范提供的能力可以让 AI 调用；其他不知道。
**评价**：MCP 修正到位——是规范/协议，不是「第三方能力」。

**引导轮 2**（部署链路五空 + `query()` 是否自己写 while 循环）
**答**：不清楚。→ 按约定给答案。

**给答案（核心）**：

- 五空全是「一段在跑的程序」：SDK 把意图变成调用 → **后端**校验令牌 → **后端**分流构建/存储 → harness 把结果回填 → **后端 + 沙箱**不让模型自己发请求。所以 harness 不是文档规范，是包在模型外面一直在跑的软件：**跑循环、管状态、执行工具、施加权限、出错恢复**。
- 三层区分：**Harness = 操作系统**（拥有循环与状态）；**Framework = 开发框架**（帮你拼 agent 的库，工具定义/提示词模板/状态机写法）；**MCP = 设备驱动接口标准**（工具描述/发现/调用格式）。模型 = CPU，上下文 = 内存。
- `query()` 是 SDK 自己把循环跑完的，你没写 while 循环——那个循环就是 harness 的一部分。DeepAgents / OpenAI Agents SDK 偏 framework 一侧；会话链路收口到 Claude Agent SDK 本质是换了一套 harness。

### 考核 1：拿掉 harness，只留「模型 + 一个工具函数」会怎样？

**答**：没有 harness 模型就无法调用工具函数了吧。
**评价**：对一半。更准的说法是「模型能**说出**要调什么，但没有执行者」——而且补上执行器也还不够。

### 考核 2：手动补执行器、把结果贴回模型，算 Agent 了吗？还缺什么？

**答**：只解决了这一轮调工具 A；如果模型拿到结果后还要调其他工具，没有执行器处理；用户中途中断、执行出错也没有对应处理。
**评价**：✅ 到位。说出了 harness 的三件事——**循环**（结果回填 → 决定下一步）、**状态**（记着到哪一步）、**收场**（取消/失败/重试/旧结果不覆盖新状态）。

### 考核 3（陷阱题）：改成 MCP 工具后的安全性提升，来自协议本身还是后端校验？凭证给模型还安全吗？

**引导轮**（三道事实题）：① 令牌绑定是 MCP 规定还是后端逻辑规定 ② 换成「模型输出 JSON、后端执行」但保留全部校验，安全性会不会变 ③ MCP 统一的是「怎么调」还是「谁能调」
**答**：① **后端逻辑规定的** ✅ ② 不知道 ③ 因为 MCP 是规范，按规范写模型都能调用 ✅

**② 给答案**：

> **安全性基本不变。MCP 是接口标准，不是安全边界。**
>
> - 安全来自后端受控通道：令牌绑定本次操作、先做冲突和分叉检查、凭证不出后端——跟用什么协议无关。
> - MCP 解决**互操作**：统一工具的描述/发现/调用格式，换模型、换框架都能复用同一套工具。它管「怎么调」，不管「谁能调」。
> - 反证：凭证放在模型能读到的地方，接了 MCP 一样不安全（注入后照样能拿凭证乱调）。

### 考核 4（收尾，练口述）：两三句话答「改成 MCP 后安全性提升在哪儿」

**答**：安全性提升其实不在于用了 MCP，MCP 只是将部署流程抽成一个方法，纯后台逻辑也能实现，只是因为我们做的是 agent 所以用 MCP 这种协议；安全性主要在后端提供了一套方案——**令牌绑定本次操作，而不是把凭证直接给大模型**。

**评价**：✅ 过关。四层都说到了：否定协议功劳、说清 MCP 的实际作用、点出为什么用、说清安全来自哪。没归错功劳，这是做过的人才有的判断。

### 定稿答案（面试可直接讲）

> Harness 是包在模型外面、一直在跑的那层软件：它跑循环、管状态、执行工具、施加权限、出错时恢复。我们平台做的就是这一层——沙箱里的 Git、预览、部署、权限收口、调用链观测，都不是模型自己做的。
>
> 它和 framework、MCP 不是一回事：framework 帮你拼 agent，MCP 统一工具的描述与调用格式，而 harness 是真正拥有循环和状态的那层。类比的话，模型是 CPU，上下文是内存，harness 是操作系统。
>
> 顺带说清楚一点：我们接 MCP 带来的安全性提升**不来自协议**，来自后端另加的受控通道——令牌绑定本次操作、凭证不给模型。MCP 解决的是工具复用。

**本题结论**：通过。两个注意点：
1. 用 harness 这个词必须能自己解释清楚，别只抛词。
2. 「MCP 只是把部署流程抽成一个方法」可以再精确一点：**统一工具的描述、发现与调用格式**——「抽成方法」容易让人以为 MCP 负责执行逻辑。
