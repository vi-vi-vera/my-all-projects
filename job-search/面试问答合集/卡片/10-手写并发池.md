# 卡 10 · 手写并发池（带重试）（提纲 4.9）

> 定级：L2（骨架正确，漏一个减号）｜ 2026-11-17 实写 + 实测

## 规格

```js
pool(tasks, { limit, retries }) → Promise<Result[]>
tasks: Array<() => Promise<any>>     // 函数数组，不是 Promise 数组
Result = { ok: true, value } | { ok: false, error }
```
三条硬要求：① 同时运行数 ≤ limit ② 失败重试 ≤ retries，用尽才记失败 ③ results 顺序与 tasks 一致

## 四个状态变量（骨架就这四样）

```js
const results = new Array(tasks.length)
let nextIndex = 0     // 下一个要取的任务
let running = 0       // 当前在跑的
let finished = 0      // 已出结论的（成功或重试耗尽）
```

**核心循环：`pump()` 补位 —— 完成一个补一个。**
不能用 `forEach` 一次发完，那样中间空出的槽位没人补，等于没有并发限制。

## 正确实现（实测通过）

```js
function pool(tasks, { limit = 2, retries = 2 } = {}) {
  return new Promise((resolve, reject) => {
    if (tasks.length === 0) return resolve([])

    const results = new Array(tasks.length)
    let nextIndex = 0, running = 0, finished = 0
    let aborted = false                     // fail-fast 用

    function done() {
      running--                             // ★ 先还槽位
      finished++
      if (aborted) return
      if (finished === tasks.length) resolve(results)
      else pump()                           // ★ 再补位
    }

    function runOne(i) {
      let retry = 0
      const run = () => {
        Promise.resolve()                   // ★ 包一层，捕获同步抛错
          .then(() => tasks[i]())           // ★ 重试 = 重新调用函数
          .then(
            (value) => { results[i] = { ok: true, value }; done() },
            (error) => {
              if (retry < retries) { retry++; run() }
              else { results[i] = { ok: false, error }; done() }
            }
          )
      }
      run()
    }

    function pump() {
      while (!aborted && running < limit && nextIndex < tasks.length) {
        runOne(nextIndex)
        nextIndex++
        running++                           // ★ 与 done() 里的 -- 必须成对
      }
    }

    pump()
  })
}
```

## 三个坑（当天踩过的）

**① 漏 `running--`** → 最典型的 bug
表现：**不报错、不 resolve、进程静默退出**。`running` 涨到 `limit` 就再不降，`pump` 的 while 永不成立，剩下的任务永远不启动。
> 自查习惯：**写完问一句「哪个状态没人回收」**。增和减必须成对出现。

**② 不包 `Promise.resolve().then()`** → 同步抛错直接冒泡出 executor → **整个 pool reject**，而不是记一条 `{ok:false}`。

**③ 重试重放 Promise** → 错的。rejected 的 Promise 不可复用，**必须重新调用函数**。这就是「tasks 必须是函数」的根本原因（接卡 07 的 eager vs lazy）。

## 测试用例（必须全覆盖）

| 用例 | 期望 |
|---|---|
| 正常成功 | `{ok:true, value}` |
| 失败 N 次后成功（N ≤ retries）| `{ok:true}`，且重试次数对 |
| 一直失败（重试耗尽）| `{ok:false, error}` |
| **同步抛错** | `{ok:false, error}`，不是整体 reject |
| 空数组 | 立刻 `[]` |
| `limit > tasks.length` | 全部成功，不死锁 |
| 结果顺序 | 与传入一致（按下标存）|

## 变体（面试常追问）

**fail-fast：任一失败就整体 reject，且不再启动新任务**
需要三处改动：`aborted` 标志 → 失败时置位 + `reject` → `pump` 的 while 和 `done` 都检查。
**已发出的任务无法取消**（Promise 没有取消能力），会跑完、结果丢弃、资源照烧。
> 真要止损必须让任务自己支持 `AbortController` —— 这就是「可取消的 Promise」变体，也能接案例 3 的 cancel 状态机。

**加退避**
```js
if (retry < retries) { retry++; setTimeout(run, 300) }
```
`retry++` 放 `setTimeout` 外面（放里面一旦重复触发就计数错乱）。
耗时公式：**`(retries + 1) × 单次执行耗时 + retries × 退避`**
取舍：**退避期间 `running` 不减 = 槽位被占**。limit 小 + 集体失败时会一起等；另一种做法是退避时先还槽位（代价是突破"同时运行数"的语义）。

## 复杂度（面试必问）

- 时间：**O(⌈n / limit⌉ × 单次耗时 × (retries+1))**，近似 `O(n/limit)`
- 空间：**O(n)**（结果数组）+ **O(1)** 状态变量

## 我的理解（原话 · 2026-11-17）

> 「先输出 m1 → 触发引入，去执行 a 文件，输出 a1 a2 → 回到引入输出 m2 → 读到引入直接读取缓存 → 输出 m3 true」

（结构写法是他自己搭的：`nextIndex / running / finished / pump()` 四件套，与标准解一致。）

**当天答错/漏掉的**
| 项 | 正确 |
|---|---|
| 漏 `running--` | 必须成对，且**先减再 pump** |
| fail-fast 只加 `reject` | 还要 `aborted` 标志拦住后续补位 |
| 退避后总耗时 = `retries × 300ms` | 漏了执行时间：`(retries+1)×执行 + retries×300` |

## 防抖 / 节流（2026-11-19）

### 区别一句话

| | 执行时机 | 场景 |
|---|---|---|
| **防抖** | **停止触发 N 秒后**才执行一次 | 搜索框输入（停手才发请求）、resize |
| **节流** | **每 N 秒最多一次**（固定节奏）| 滚动、拖拽、按钮防连点 |

### 手写 debounce（基础版）

```js
function debounce(fn, delay = 300, immediate = false) {
  let timer = null                    // ① 闭包持有，跨调用存活
  return function (...args) {
    if (timer) clearTimeout(timer)    // ② 先清掉上一次的
    if (immediate) {
      const callNow = !timer          // 冷却中？false：true
      timer = setTimeout(() => { timer = null }, delay)
      if (callNow) fn.apply(this, args)
    } else {
      timer = setTimeout(() => fn.apply(this, args), delay)
    }
  }
}
```

**三个考点**：

**① 为什么 `timer` 放闭包里**：否则每次调用都是新变量，`clearTimeout` 清不到上一次。→ 和"函数组件没记忆，记忆放外面"同一原理。

**② 为什么 `fn.apply(this, args)` 不是 `fn()`**：
```js
const obj = { name: '搜索框', run: debounce(function (kw) { console.log(this.name, kw) }, 300) }
obj.run('React')   // 期望 "搜索框 React"
```
返回的函数被 `obj.run()` 调用，`this = obj`；箭头函数里的 `this` 继承返回函数的 this；`apply` 把 `obj` 和参数原样传给 fn。**写 `fn(...args)` → this 变 undefined（严格模式）。这是手写题最常挂的地方。**

**③ immediate 版**：`callNow = !timer` 判断是否在冷却中。**`clearTimeout` 不会把 `timer` 置 null**，所以 `!timer` 才能正确判断。

**必被追问**：基础版第一次触发是**延迟**执行（要等完第一个 delay），只有 immediate 版第一次**立即**执行。

### 手写 throttle（两版差异是加分点）

```js
// 时间戳版：第一次立即执行，最后一次可能丢掉
function throttle(fn, wait = 300) {
  let last = 0
  return function (...args) {
    const now = Date.now()
    if (now - last >= wait) { last = now; fn.apply(this, args) }
  }
}

// 定时器版：第一次延迟，最后一次能补一次
function throttle2(fn, wait = 300) {
  let timer = null
  return function (...args) {
    if (timer) return
    timer = setTimeout(() => { fn.apply(this, args); timer = null }, wait)
  }
}
```
> **时间戳版首次立即执行、末次不执行；定时器版首次延迟、末次执行。**

## 深拷贝（2026-11-20）

### 必考三项（写到这三个就是及格）

| 项 | 做法 |
|---|---|
| **循环引用** | `WeakMap` 记录「原对象 → 副本」；**先 set 再递归**（顺序反了会栈溢出）|
| **Date / RegExp** | 单独构造：`new Date(target)` / `new RegExp(source, flags)` |
| **保持原型** | `Object.create(Object.getPrototypeOf(target))` |

### 加分三项（能补上说明想过边界）

| 项 | 洞 | 修法 |
|---|---|---|
| **Symbol 键** | `for...in` 只遍历可枚举的字符串键 | `Reflect.ownKeys`（含 Symbol）|
| **Map / Set** | `for...in` 拿不到自有可枚举属性 → 克隆出空壳 | 单独判断，走 `forEach` 递归 |
| **`Object.create(null)`** | 没有 `constructor` → `new target.constructor()` 抛错 | 用 `Object.create(getPrototypeOf())`|

### 完整版

```js
function deepClone(target, map = new WeakMap()) {
  if (target === null || typeof target !== 'object') return target   // 原始值 + 函数
  if (map.has(target)) return map.get(target)                        // 循环引用

  if (target instanceof Date) return new Date(target)
  if (target instanceof RegExp) return new RegExp(target.source, target.flags)

  if (target instanceof Map) {
    const m = new Map(); map.set(target, m)
    target.forEach((v, k) => m.set(deepClone(k, map), deepClone(v, map)))
    return m
  }
  if (target instanceof Set) {
    const s = new Set(); map.set(target, s)
    target.forEach(v => s.add(deepClone(v, map)))
    return s
  }

  const clone = Object.create(Object.getPrototypeOf(target))         // 不调构造函数
  map.set(target, clone)

  for (const key of Reflect.ownKeys(target)) {
    if (!Object.getOwnPropertyDescriptor(target, key).enumerable) continue
    clone[key] = deepClone(target[key], map)
  }
  return clone
}
```

### 为什么 `Object.create(getPrototypeOf())` 比 `new target.constructor()` 好

1. **不调构造函数**——构造可能有副作用、可能要求参数
2. **自动保持原型**——`instanceof` 正常
3. **对 `Object.create(null)` 也成立**——原型是 null 就照抄 null

### 面试收尾句（说明你知道什么时候不该自己写）

> 「实际项目里优先用 `structuredClone()`——原生支持循环引用；手写只在需要处理函数或环境不支持时用。」
