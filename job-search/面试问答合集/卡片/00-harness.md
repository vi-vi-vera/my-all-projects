# 卡 00 · Agent Harness（提纲 1.0，统领概念）

> 定级：L2（待明日盲测确认 L3）｜ 2026-11-16

## 3 句骨架

1. **模型是 CPU，上下文窗口是内存，harness 是操作系统**——它不是「范式」，是一层**运行时软件**：跑控制循环、执行工具、管上下文、施加权限与沙箱、维护状态与恢复、上报可观测。
2. **framework 是零件箱，harness 是用零件装出来的机器**。LangChain 给组件、LangGraph 给图编排 + checkpointer、CrewAI 给多角色分工。判据：**拥有循环和状态的是 harness，不是 framework**。
3. **MCP 是 Agent ↔ 工具的接入协议**（host–client–server，工具/资源/prompt 三类原语）；模型只产出 tool call 意图，**真正发请求的是 harness**。ACP 管 Agent ↔ 客户端 / Agent ↔ Agent（会话生命周期、中断、消息格式）。

## 层次辨析（高频反问）

> **「LangGraph 就是 harness 吧？」**
> → LangGraph 给的是 harness 的**控制平面骨架**——循环和状态它确实管。但它不管**治理层**：没有权限模型、没有沙箱与凭证隔离、没有工具接入协议（MCP 的事）、没有可观测口径。
> **一个能上生产的 harness = 骨架 + 治理。** 这也是我们生产用 Agent SDK 而不是 LangChain 系的原因——不是不会用，是治理层得自己长。

## Trade-off

- **自己搭 harness vs 用现成框架**：框架起步快，但治理层（权限/沙箱/审计）迟早要自己长；自己搭可控，代价是循环和状态机得自己维护。
- **单 Agent + Skills vs 多 Agent**：单 Agent 上下文共享、可控性高、成本低；多 Agent 并行快但 token 翻十几倍、决策分散、上下文不共享。

## 边界

多 Agent 编排**没做过**（平台是单 Agent + Skills）。被问就说现状，再讲「如果做我会怎么拆」，不装做过。

## 最容易被追死的一问

> **「你做过 harness 的哪几块？」** → 六块全有落点，重点展开**权**和**观**（深水区），其余一句话带过。
