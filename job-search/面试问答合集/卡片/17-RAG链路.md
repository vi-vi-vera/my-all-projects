# 卡 17 · RAG 链路（1.7）

> 定级：L2（加分题）｜ 2026-11-21（D5）
> **红线：生产上没做过 RAG，也没微调。** 只讲链路、取舍和排查思路，不包装成经历。
> 素材：`待补答案-AI专项.md` 1.7-1 ~ 1.7-4

## 3 句骨架

1. **RAG 分离线、在线两段**：离线是"解析清洗 → 按结构切块 → 带元数据向量化入库"，在线是"改写问题 → 混合召回 → rerank → 拼 prompt → 生成并校验引用"。
2. **召回质量决定上限**——切块和清洗没做好，模型再强也答不对；所以要**把召回和生成分开评测**，别在 prompt 上打转。
3. **RAG 管"说什么"，微调管"怎么说"**；顺序是先 prompt → 再 RAG → 最后微调，因为迭代速度差一个数量级（一分钟 / 十分钟 / 几天）。

## 一、离线：建索引（5 步）

| # | 步骤 | 关键点 |
|---|---|---|
| 1 | 解析 | PDF / Word / HTML → 文本 **+ 结构**。必须保住标题层级，别只剩一坨纯文本。扫描件走 OCR |
| 2 | 清洗 | 去页眉页脚、水印、目录页、重复章节、乱码。最脏，也最容易被跳过 |
| 3 | 切块 | 按**结构边界**（标题 / 段落 / 条款 / 函数）切，不按字数硬切；设上限，相邻留**少量重叠**；**表格整表保留或按行切但每行带表头**；代码按函数/类切 |
| 4 | 富化 | 每块挂元数据：文档 id、版本、标题路径、更新时间、**权限**。标题路径要**拼进正文再向量化**（"3.2 结算规则"的正文里可能压根没有"结算"二字） |
| 5 | 入库 | 嵌入模型转向量，原文 + 元数据一起存 |

**切块的取舍**（不背固定数字）：切太大 → 一块混多主题、噪声多、浪费上下文；切太小 → 语义被拆散、缺上下文。具体多大要拿真实问题 + 评测样例试，**不拍脑袋报数字**。

## 二、在线：检索 → 生成（5 步）

| # | 步骤 | 关键点 |
|---|---|---|
| 6 | **查询理解 / 改写** | 发生在**检索之前**。多轮补指代（"它"→"结算规则"）、口语转检索式、必要时扩成多个 query |
| 7 | 召回（粗排） | **向量 + 关键词混合**：专有名词、编号、错误码关键词更准。加元数据过滤（权限、时间）。取 top 30~50 |
| 8 | **rerank（精排）** | 更精细的模型对"问题 × 每个候选"逐一打分重排，留 top 3~5。准但慢且贵 → 只处理小候选集 |
| 9 | 组装 prompt | 材料 + 编号 `[1][2]` + 指令：只依据材料回答、必须标引用、材料没有就说没有 |
| 10 | 生成 + 兜底 | 校验引用编号真实存在（不让模型自己写出处）；**相似度低于阈值就明说"没找到依据"** |

## 三、最危险的一种失败：错得理直气壮

```
用户问"它是自动生效还是需要审批？"（上文在问结算规则）
→ 不改写，直接 embedding
→ "它"没有信息量，整句语义偏向"审批 / 生效流程"这类通用问题
→ 召回的是一堆通用审批流程文档，真正的"结算规则"根本没进候选
→ 模型拿到错误材料，照样流利作答，还带引用
```

用户看到的不是"我找不到"，而是**一个自信的错误答案**。所以阈值兜底 + 引用校验比 prompt 调优重要。

## 四、prompt / RAG / 微调三分叉（连问必考）

| | 改什么 | 生效速度 | 成本 | 适合 |
|---|---|---|---|---|
| 提示词 | 指令 | 立刻 | 几乎为零 | 规则、格式、语气、边界 |
| **RAG** | 给它资料 | 重建索引即可 | 中 | 知识多、更新快、**要引用** |
| 微调 | 模型行为 | 训练 + 发布 | 高 | 固定格式、领域话术、分类判断、降本 |

- 微调改的是"**怎么做**"（格式/语气/术语/判断标准），不改"知道什么"（事实会过期，细节训不牢）
- 形式：SFT（照着样本学）/ LoRA（只训少量附加参数，工程最常用）/ DPO（用"这个比那个好"调风格）
- 成本大头不是训练，是**标注和评估**；上线后模型变成要版本管理、能回滚的产物
- 微调划算要三条同时成立：任务重复且量大、prompt 已压不出提升、RAG 也解决不了

## 五、边界（诚实说）

> "这块我没有生产落地，没做过 RAG，也没做过微调。我的平台是**提示词 + 工具 + 沙箱执行**。链路我清楚，如果加外部知识我会**先上 RAG 不先考虑微调**，因为知识更新频率高、还要能引用。"

**唯一允许的类比**：Skills 渐进式加载（只放名单、正文按需读）和"按需注入相关片段、不全量塞上下文"是同一个思路——**必须说明这是类比，不是做过**。

## 我的理解（原话 · 2026-11-21）

> "首先是进行文档处理，然后对这些文档进行分片和 embedding 入库，当用户提问时对提示词也进行 embedding，拿 embedding 后的提示词去库里做召回，根据相关性排序，然后拿到召回的数据和提示词，根据提问方式对 prompt 进行重写，将重写后的 prompt 给 llm 进行回答。"

> "这里最重要的其实是第一步文档处理，需要进行数据清洗、表格、pdf 这些怎么转换……分片怎么分，重叠量要设置多少，这些前置的处理会影响后续的召回质量。"

## 当天说歪的

1. **把 query 改写放到了检索之后** → 改写必须在检索**前**，否则召回的已经是"改写前那句话"的结果。
2. **"根据相关性排序"混同 rerank** → 要分粗排（向量/关键词召回）和精排（rerank）两层。
3. 链路里漏了：**引用怎么产生与校验**、**没检索到怎么办（阈值）**、**文档更新怎么增量重建**、**元数据/权限过滤**。

## 追问备用

| 追问 | 答法 |
|---|---|
| 为什么不全用 rerank？ | 要对每个候选逐一计算，慢且贵，不适合全库，只精排小候选集 |
| 召回不准怎么办？ | 先分清哪一环：切块？表述差距？检索方式？→ 调切块 / 改写扩展 / 混合检索 / 元数据过滤 |
| 怎么评召回？ | 一批问题 + 对应正确块，看是否召回、排第几。召回与生成分开度量 |
| 引用会不会是编的？ | 会。引用要由系统按真实召回的块生成并校验编号存在，不让模型自己写 |
| 文档更新了？ | 按 doc_id + 版本找旧块删掉重入，不整库重建 |
| 表格怎么切？ | 整表保留，或按行切但每行带表头；不按字数硬切 |
