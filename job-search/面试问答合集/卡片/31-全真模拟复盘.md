## 三个致命问题

1. **自我介绍主线倒置**：投 AI 岗，前 40 秒在讲前端经历。
2. **举不出“具体冲突”**：讲了状态枚举和优先级，但拿不出「旧代码错、新代码对」的实例 → 面试官判定“设计没落地”。
3. **Demo 塞了 3 分钟信息进 90 秒**：CLB、网关、pod 定位、探活、重试全上了，屏幕上却只有页面。**屏幕上没有的东西，90 秒里一句都不讲。**

## 编码瑕疵（防抖）

- `return debounced` 不该有——`debounced` 应返回 **`fn` 的返回值**或 undefined，返回自身会误导调用方
- **做对了但没说出来**：`immediate` 模式下 `cancel()` 除了 `clearTimeout`，**还必须把 timer 置 null**，否则下次 `!timer` 判断失真，不会立即执行。**做对 + 说出来 = 满分；做对不说 = 半分**

# 三份定稿

## ① 自我介绍（55 秒，背）

> “我四年开发经验，近一年转做内部 AI Agent 平台，负责**执行与预览**这条链路。
> 主要三块：一是 Git 操作，页面入口 + 后台分叉冲突检测 + 短期令牌的受控执行；二是沙箱预览，把散落各处的预览状态收敛成一个状态机；三是部署和上传。
> 技术栈 Node + TS + React。
> 我比较擅长**从方案推到上线**，包括踩坑和收尾。”

**改掉的四处**：删学校（社招不关心）、"四年+一年"改"四年，近一年转"、结尾换成"从方案到上线"（比"0→1 部署"贴 AI 岗）、错字。

## ② 状态机冲突例子（必须能脱口而出）

> “沙箱健康、但工作区文件被清空时，按旧逻辑先看沙箱状态，健康就显示 loading 去启动——**用户看到的是无限转圈，只能刷新页面**。
> 改完之后把「文件为空」提到沙箱检查之前，直接显示空态，并给一个「重新生成」的入口。”

**关键在最后半句**：空态不是终点，要告诉用户下一步能做什么——**这才是设计，不是补丁**。

## ③ Demo（80 秒，A 版）

| 秒 | 画面 | 台词 |
|---|---|---|
| 0–10 | 打开已有项目 | “这是我们的 Agent 平台，用户在对话里让模型**直接改代码**。” |
| 10–30 | 输入需求 → 流式 + 工具卡片 | “它边流式输出边调工具改文件，**每次调用的参数和结果都能看到**。” |
| 30–50 | 预览出现 | “改动在沙箱里执行，服务起来后右侧就是这个 iframe。**预览用独立域名，和主站不同源**，里面跑的代码碰不到后台登录态。” |
| 50–75 | 再改一次 → 自动更新 | “第二次改动不用点任何按钮。**最难的是判定「新内容真的生效」才切换**，否则会闪一下旧版本。” |
| 75–90 | 定格 | “这条链路我主要负责**预览状态机和预览链路**。边界：**断线能续，进程挂了不能续**。” |

**删掉（留作追问的料）**：工蜂导入、status 轮询细节、CLB / 网关 / pod 定位、探活与重试。

**第 4 段是全场唯一的「判断」**——没有它，就是产品演示，不是技术面试。
