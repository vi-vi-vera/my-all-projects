# 卡 25 · TS 泛型与收窄（4.2）

> 定级：L1→L2（概念今天从零建，需再练一次手写）｜ 2026-11-24（D8）

## 前提（一切推论从这句来）

> **TS 的类型只在编译期存在，运行时全被擦掉。** 它的价值是**写的时候报错**，不是运行时保护。

## 一、收窄（narrowing）

**定义**：用判断把「可能是 A 也可能是 B」缩成「一定是 A」。

```ts
let v: string | number = 'abc';
v.toUpperCase();          // ❌ 可能是 number
if (typeof v === 'string') {
  v.toUpperCase();        // ✅ 这里一定是 string
}
```

| 手段 | 回答什么 | 例子 |
|---|---|---|
| `typeof` | 哪种原始类型 | `typeof v === 'string'` |
| `in` | 有没有这个属性 | `'r' in s` |
| `instanceof` | 哪个类的实例 | `e instanceof Error` |
| **判别联合** | 哪个标签 | `s.kind === 'circle'` |
| **自定义守卫** | 复杂判断包成函数 | `function isX(v): v is X` |

### 判别联合（最常用）

```ts
type Shape =
  | { kind: 'circle'; r: number }
  | { kind: 'square'; size: number };

function area(s: Shape) {
  if (s.kind === 'circle') return Math.PI * s.r ** 2;
  return s.size ** 2;
}
```

`kind: 'circle'` 里的 `'circle'` 是**字面量类型**（只能是这个值）。判掉一个值，另一个就确定了 → TS 能精确收窄。

**为什么它比 `in` 好**：字面量标签能精确区分；`in` 只能猜“有这属性大概是那个”。

### 自定义守卫

```ts
function isString(v: unknown): v is string {
  return typeof v === 'string';
}
```
`v is string` = “我保证返回 true 时 v 是 string”。**这是给 TS 的承诺，写错了它不管**。

## 二、穷尽检查（enums / union 漏分支的兜底）

```ts
function assertNever(x: never): never {
  throw new Error(`漏了分支: ${JSON.stringify(x)}`);
}

function area(s: Shape): number {
  switch (s.kind) {
    case 'circle': return Math.PI * s.r ** 2;
    case 'square': return s.size ** 2;
    default: return assertNever(s);
  }
}
```

**原理**：分支处理完，`default` 里的 `s` 是“不可能的类型”，TS 用 `never`（空集）表示。新增分支没处理 → `s` 变成新类型 → **不能赋给 `never` → 编译报错**。

**为什么重要**：没有它，加分支后 `s.size` 在 square 上合法 → 编译过 → 静默返回 `NaN`（不是崩，更危险）。

## 三、泛型

**动机**：不写死类型，但不丢类型。

```ts
function id(x: any) { return x; }        // 类型丢了
function id<T>(x: T): T { return x; }    // T 自动推断
const a = id('abc');                     // string ✅
```

> **泛型 = 让「类型」也能当参数传。**

| 语法 | 含义 |
|---|---|
| `<T>` | 声明类型参数 |
| `<T extends X>` | T 必须是 X 的一种（**约束**，不是继承） |
| `keyof T` | T 的所有字段名组成的联合类型 |
| `T[K]` | T 里 K 这个字段的**类型** |

```ts
type User = { id: number; name: string };
type K = keyof User;      // 'id' | 'name'
type N = User['name'];    // string
```

### 综合例题：pluck

```ts
function pluck<T, K extends keyof T>(arr: T[], key: K): T[K][] {
  return arr.map(item => item[key]);
}

pluck([{ id: 1, name: 'a' }], 'name');   // string[]
pluck([{ id: 1, name: 'a' }], 'age');    // ❌ 'age' 不在 keyof T 里
```

## 四、TS 默认不安全的一个点

```ts
function first<T>(arr: T[]): T | undefined { return arr[0]; }
```

**`arr[0]` 在空数组时是 `undefined`，但默认配置下 TS 认为它是 `T`** —— 除非打开 `noUncheckedIndexedAccess`。

- 默认（关闭）：`arr[0]` 类型 = `T` → 写 `: T` 不报错，但**类型在撒谎**
- 打开后：`arr[0]` 类型 = `T | undefined` → 写 `: T` 会报错，逼你处理空数组

面试可讲：**“TS 的索引访问默认是不安全的，因为要兼容老代码；开 `noUncheckedIndexedAccess` 才严谨。”**

## 五、工具类型（提一句即可）

`Partial<T>` / `Required<T>` / `Pick<T, K>` / `Omit<T, K>` / `Record<K, V>` / `ReturnType<F>` / `Parameters<F>`。

能在被问到时说“常用这几个，`Pick`/`Omit` 做视图模型裁剪”就够。
