# 卡 23 · 系统设计④ 沙箱执行服务（8 分钟）

> 定级：L2（框架成型，需再练一次口述）｜ 2026-11-23（D7）
> 题目一句话：**"设计一个服务，能安全地执行 AI 生成的代码。"**
> 这题考的是**安全边界**，不是业务分层。"关键设计点"那一层几乎是全部分数。

## 一个比喻立住全题

> **沙箱 = 给不可信的代码划一个笼子。**

所有设计问题归到四维：

| 维度 | 问什么 |
|---|---|
| **能不能出去** | 隔离级别：进程 / 容器 / 微虚拟机 |
| **能用多少** | CPU、内存、时间、磁盘 |
| **能碰什么** | 文件系统、网络、敏感操作令牌 |
| **出事能不能查** | 审计：谁跑了什么、退出码、产物 |

**开场先说这四个字：隔离、资源、权限、审计。**

## 第 1 步：澄清（4 问 + 为什么重要）

| 问题 | 为什么它改变设计 |
|---|---|
| 代码是谁写的？模型生成 / 用户上传 | 决定隔离强度：自家模型 vs 陌生用户，后者按恶意代码对待 |
| 要跑多久？ | 决定超时策略、要不要异步任务 |
| 能碰什么？只读/写/联网/装依赖 | 决定文件系统挂载与网络策略 |
| 单租户 / 多租户？ | **决定"进程隔离够不够"的那一问** |

> 爽点：**问对了，隔离级别是推出来的，不是背出来的。**

## 第 2 步：五层

| 层 | 职责 |
|---|---|
| 接入/调度 | 收请求、排队、分配沙箱（并发满怎么办） |
| **生命周期** | 创建/复用/销毁、空闲回收、**超时强杀** |
| **隔离执行** | 进程组、资源上限、文件挂载、工作目录 |
| 权限与能力 | 只读挂载、默认禁网/白名单、受控令牌、工具白名单 |
| 观测审计 | 命令、退出码、耗时、资源峰值、产物留存 |

**切分理由**：生命周期管"笼子什么时候建、什么时候拆"，隔离执行管"笼子里怎么关"。混在一起，超时回收和资源释放会互相踩。

## 第 3 步：主流程

> 请求 → 排队 → 分配/新建沙箱 → 代码目录**只读挂载** + 临时工作区 → 设资源上限 → 执行 → 收 stdout 与产物 → **回收整个沙箱**（或杀整个进程组）→ 审计落库。

## 第 4 步：三个 trade-off

### ① 隔离级别

| 级别 | 强度 | 启动 | 代价 |
|---|---|---|---|
| 进程 | 弱（同内核、共享文件系统、可读环境变量） | 最快 | 防不住恶意代码 |
| 容器 | 中（namespace + cgroup，仍共享内核） | 中 | 内核漏洞可逃逸 |
| 微虚拟机 | 强（硬件级） | 慢、重 | 成本高、调试难 |

> 选择逻辑看澄清第 4 问：**单租户 + 自家代码 → 进程够用；对外多租户 + 不可信代码 → 容器或微虚拟机**。不是越强越好，强度上一档，启动时延和成本都上一档。

### ② 复用 vs 每次新建

> 复用省启动时间，但**上一个任务的残留会污染下一个**；每次新建干净但慢。折中是**池化预热**：提前建好，用完重置工作区放回池。

### ③ 最小权限 vs 能干活

> 只读挂载 + 默认禁网，Agent 干不了活；放开就危险。折中 = **按操作分级**：读随便、写限工作区、联网走白名单、高风险操作（推代码）走**受控令牌 + 人工确认**。

## 第 5 步：收口

> 瓶颈两个：**启动开销**（强隔离的冷启动是大头，靠池化稀释）、**逃逸面**（进程隔离防不住恶意代码）。下一步看业务：内部保持现状，对外先补隔离级别再补审计。

## 我的项目口径（2026-11-23 查代码，**不是进程隔离**）

> "隔离是**容器级**：跑在 k8s 上（阿里云 OpenSandbox），从**预热池**分配，2C4G，带 **DIND sidecar**，所以沙箱里能 `docker build/push` 做部署。命令和文件操作走沙箱内的 **execd 守护进程**。生命周期默认 24 小时，重连靠 sandboxId。代价三条：每沙箱 2C4G 的资源成本、DIND 把 docker daemon 放进沙箱放大攻击面、容器共享内核防不住内核级逃逸，所以敏感操作叠受控令牌。"

**没核实别乱说**：网络出口是否白名单、资源限制是 k8s limits 还是 rlimit、沙箱内是否 root。

## 故障域（这题最值钱的一句）

> **容器的作用不是"让问题不发生"，是"让问题出不去"。**

| | 进程隔离 | 容器 |
|---|---|---|
| 孤儿进程跑在 | 宿主机 | 沙箱容器里 |
| 影响 | 整台机器，连带别人的会话 | **只有这一个沙箱** |
| 清理 | 找 PID 一个个杀 | **销毁沙箱就干净** |

`npm install && npm run build` 超时只 kill npm → 子进程变孤儿继续吃 2C4G、继续写工作区；沙箱活 24h 就一直脏。**正确动作是回收整个笼子**，不是 kill 一个 PID。
