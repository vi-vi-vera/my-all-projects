# 卡 16 · 成本与延迟（1.6）

> 定级：L2（加分题，能讲清结构与冲突即可，不包装成生产经验）｜ 2026-11-21（D5）
> 素材：`待补答案-AI专项.md` 1.6-3

## 3 句骨架

1. **长对话的成本大头不是回答太长，是每一轮都把系统提示、工具定义、历史重新发一遍**——十轮里约 87% 的 input 是重复付费。
2. **能降总量的只有两条：减量、省轮次**。缓存降的是**单价**不是总量，而且断点是 SDK 打的，开发者能控的只有"前缀稳定"——它是**约束**，不是手段。
3. **缓存和清理天然打架**：清历史就改前缀，每轮清等于缓存永不命中，比不清**贵十倍**。所以规则是粗粒度、攒阈值清一次、清完保持稳定，或者干脆切会话。

## 一、先算账（这是这题的入场券）

系统提示 8k + 工具定义 4k = 固定 12k，每轮新增 1k。

| 轮次 | 这一次要发 |
|---|---|
| 1 | 13k |
| 5 | 17k |
| 10 | 22k |
| **十轮累计** | **175k** |

> 175k 里真正的新信息只有 **22k**（12k 固定 + 10k 新对话），剩下 **153k 全是重复付费，占 87%**。

增长形态的准确说法：**单轮线性、累计二次**。说"指数级"会被抓（指数是 2ⁿ，十轮就爆了，这里才 175k）。

工具结果更贵：模型读一次大文件，那份内容**进历史后每轮都要重发**，一次读取 = 后面每轮都付钱。

## 二、四个方向

| 方向 | 做什么 | 收益 | 风险 |
|---|---|---|---|
| **减量**（最高） | ① 工具返回值瘦身（读文件限行、搜索只回匹配行、命令输出截断）<br>② 清理已用过的工具结果（大块换摘要）<br>③ 按任务切会话 | 高 | 工具结果要保结论和错误，丢细节有风险；切会话后翻旧账要跨会话 |
| **省轮次** | 并行工具调用一次发出；确定性步骤交给代码，别让模型试错 | 中 | 需要工具支持并行 |
| **算准** | 成本分四类统计：普通输入 / 缓存写入 / 缓存读取 / 输出 | —— | 混着算会得出错误结论，甚至把优化做成负收益 |
| **缓存**（约束） | 保证前缀稳定，变化内容放最后 | 降单价 | 10 分钟级 TTL；写入加价；中断点由 SDK 决定 |

## 三、缓存为什么是"约束"不是"手段"（最容易被追死的一问）

追问：「你们有 prompt caching，成本是不是就不用管了？」

答：
> 缓存降的是**单价**，不是**总量**——命中部分按约 0.1x 计费，但输入 token 一个没少。而且断点是 SDK 打的，写缓存那一下还要加价，缓存也有 TTL。所以我把它当成**约束**：保证前缀不变，别把时间戳、用户 ID、随机串放提示词开头，会变的内容放最后。真正能降总量的是减量和省轮次。

## 四、缓存 × 清理的冲突（这题最值钱的一段）

缓存按**前缀**算：从开头到断点整段一模一样才命中。在中间删内容 → **从删的位置往后全失效**，但删点之前（系统提示、工具定义）缓存还在。所以不是全废，是**消息段失效**。

历史 100k、命中价 0.1x 的三种账：

| 做法 | 每轮等效成本 | 结论 |
|---|---|---|
| 不清理 | 100k × 0.1 = **10k** | 稳定 |
| **每轮清理** | 前缀每轮变 → **100k 全价** | **比不清贵十倍** |
| 攒到阈值清一次（清到 40k） | 清理那轮付 40k 全价，之后每轮 4k | 约五轮回本 |

规则：**粗粒度、一次性、清完保持稳定**。两个好时机：缓存本来就要过期时、任务切换时。

更干净的解法是**切会话**：旧会话不动（缓存不受影响），新会话只带几行摘要，历史从零开始。

## 我的理解（原话 · 2026-11-21）

> "缓存确实算一个降本手段，但是当历史记录过长时 input 会指数级增长，最好搭配返回内容截断、历史上下文截断或压缩，但这些都会造成模型记忆漂移的问题，目前最好的解法还是使用中根据不同的推进主题，开对应的会话窗口，并控制上下文长度。"

> "B（攒着清）。每次都清的话就无法使用缓存命中价了。"

## 当天答错 / 说歪的

1. **"input 指数级增长"** → 是单轮线性、累计二次。用词不精确，面试里直接扣分。
2. **"缓存是降本手段"** → 要拆成"降单价 vs 降总量"，缓存属于**约束**那一侧，一句话说清才显功力。
3. 十轮累计算成 153k（漏了第一轮与本轮新消息），口径要统一：第 n 轮 = 12k + n×1k。

## 边界（诚实说）

- **做了**：工具输出限量、Skills 渐进式加载（只放名单、正文按需读）、成本统计里把 cache token 单列。
- **没做**：工具结果的自动清理、按任务自动切会话、历史摘要压缩。
- **一句关键**：截断是为了**会话一致性**，不是为了降成本——别说反了。
- 统一句式：「这块我们没做。如果要做，我会 ___，代价是 ___。」

## 追问备用

| 追问 | 答法 |
|---|---|
| 缓存不是 SDK 做的吗？ | 是，所以我把"保证前缀稳定"当约束，不当手段 |
| 清理工具结果会让缓存失效吗？ | 会让**消息段**失效，系统提示那段还在。所以不能每轮清 |
| 多久清一次？ | 不按轮次，按**阈值或任务边界** |
| 切会话 vs 压缩怎么选？ | 任务切换用切会话；同一任务太长且不能切，用压缩。压缩保留约束和结论，只压过程 |
| 怎么知道省了多少？ | 分项看：每轮输入、缓存命中、工具结果占比。只看总 token 会判断错——用了缓存总量没降，但实际花费降了 |
