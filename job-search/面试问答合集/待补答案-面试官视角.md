## 1｜流程结构：20–35K · 3–5 年 · AI 应用/Agent 全栈（深圳，2026）

这个档位通常 **3–5 轮**：大厂 3 轮技术 + HR（部分加笔试/GM 面）；AI 创业公司常压缩为 2 轮技术（CTO/技术合伙人直接面）+ HR，且越来越多团队在二面前后夹一轮实操——现场调 Agent、改 prompt 或 takehome。

| 轮次 | 谁面 | 在筛什么 | 常见淘汰点 |
|---|---|---|---|
| 0. 电筛（10–30min，常省略） | HR/猎头 | 薪资带宽、到岗时间、动机一句话 | 期望超带宽；动机讲不清当场终止 |
| 一面（60–90min） | 组内资深工程师（未来同事） | 基础+项目真实性：JS/TS/Node 八股、手写题、项目往下挖两层 | AI 候选人最常死在基础和手写；项目一追问就空；把平台成果说成个人主导被拆穿 |
| 二面（60–90min） | 部门技术负责人 | 系统设计（8 分钟结构）+ AI 深挖：上下文、工具、安全、trade-off | 设计题堆名词没有取舍；Agent 经历被剥掉框架名后只剩「调 SDK」；被问没做过的（多 Agent/RAG/评测）硬编当场穿 |
| 三面（30–60min） | 总监/GM 或交叉面 | 定级定薪：技术视野、成长曲线、稳定性、对 AI 趋势有无自己的判断 | 转全栈/跳槽动机站不住；趋势题只会复述公众号口径 |
| HR 面（20–40min） | HRBP | 现薪期望、稳定性、offer 谈判 | 虚报现薪；吐槽前司；薪资锚死 |

三条贯穿规律：

- **二面是定价轮**。20K 还是 32K 基本在这里定：面试官会把 Agent 经历「脱水」——剥掉 SDK 和框架名看剩下什么。剩下受控通道、状态收敛、上下文管理，往上限定；剩下「写 prompt、接接口」，往前端保底岗分流。
- **评估与可观测从加分题变必答题**。「怎么知道 AI 功能变好还是变坏」答不上，会被归类为「只会堆功能」，直接影响给 AI 岗还是前端岗。
- **安全是 Agent 岗准入项不是加分项**。prompt injection、工具权限收口答不出，AI 产品团队基本直接过。

## 2｜满分题 12 道（编号对应提纲）

1. **1.0 Agent Harness 定位**（含「我做的是 harness 这一层——模型之外的循环、工具、权限和状态收敛」）——这题决定你被归入「系统工程师」还是「调 API 的」，所有案例靠它收拢成一句话；抛不出这个词或解释不清，后面每个案例都掉价。
2. **1.1 截断策略 / 上下文两边都删（案例 5）**——「只删数据库、模型侧还在续写」这个坑极少候选人真踩过，这题是「真做过 Agent 会话」的最快信号，也是你简历和答案能互证的题。
3. **1.2 prompt 六块框架**（角色/上下文/任务/格式/示例/兜底）——AI 线开场高频题，没有框架=没有方法论，面试官立刻降档。
4. **1.2 prompt/RAG/微调三分叉**——选择顺序和代价讲错，暴露从没为成本与迭代速度做过决策；你有平台真实选型（prompt+工具+沙箱）可挂。
5. **1.3 tool calling 完整流程**——你强项领域的地基，流程答不全，后面的 MCP 实战全是空中楼阁。
6. **1.3 「好用的工具」怎么定义**——description 写「何时用/何时不用」、粒度、「后端能定的不交给模型」、失败信息可自我纠正——只有真设计过工具的人才说得出这几条，是「接 MCP」和「设计工具」的分界。
7. **1.4 Agent run 状态机 + 取消 + 竞态（案例 3）**——「决策点分散→单点收敛」是二面深挖最能撑住 15 分钟的硬货，讲不出洞察就只是流程复述。
8. **1.9 注入与越权：受控通道（案例 2、4）**——Git 两条链路的真实权限边界、AI 受控写入方案（未接入界面）、部署改受控工具这条线答不出=AI 岗直接出局；答好了是你和只会 sanitize 输出的候选人的分界。
9. **1.8/1.2 评估闭环 + 诚实边界**——三步框架（正例集→全量跑→退化归因）加上「业务没建回归集、个人 demo 做过 10 条」的边界句；这题的满分恰恰靠诚实说法拿到，硬编评测数据则一追问就穿。
10. **1.5 SSE vs WebSocket + 断线恢复**——AI 产品日常就是流式，这题答不稳，面试官会怀疑你没做过生产级 AI 前端。
11. **二-1 设计 AI Agent 工作台**——二面定级题，QPilot 就是答案；讲不出「需求澄清→数据模型→状态机→错误安全→取舍」的 8 分钟结构，等于把唯一完整实战浪费了。
12. **3.3/1.6 AI 监控与普通服务不同 + token 口径（案例 6）**——token、成本、工具树、cache 口径修正是普通工程师答不上的差异化题，这是 30K 档的定薪筹码。

**其余做到「能接住」即可**：JS/TS/React/Vue/小程序八股热手；1.7 RAG 只求讲清链路；1.4 多 Agent 记住「现状+如果做我会怎么拆」两段式；1.11 模型选型记安全句（讲维度不背排名、没做过横向评测直说）；手写题按 §6 每天 3 道。唯一例外：若临时投前端保底线，把 4.6 可配置中后台设计题（案例 7）升为满分题。

## 3｜最可能被当场质疑的 5 个点

**① 「转全栈才 7 个月，凭什么算全栈？」**
应对：讲「活先来了、我接得住」——沙箱 Git、预览、部署的方案实现上线都是我做的，再主动划界「AI 应用链上的全栈，不做通用后端，数据库中间件不如专业后端深」。
不该说：「前后端没什么差别，上手挺容易」——把判断力说成了轻率。

**② 「你的 AI 经历不就是调 SDK 吗？」**
应对：接住后直接上 harness 定位 + 受控通道主线——Git 面板预检、AI 受控写入方案、部署受控工具、身份密钥不出平台，并主动说清 Git 对话链路的边界，讲模型之外的循环、权限、状态收敛这些硬工程。
不该说：「模型训练/微调我也了解一些」——往没做过的层伸手，一个追问就穿。

**③ 「为什么不做多 Agent / RAG？」**
应对：有立场地答——单 Agent + Skills 是为了上下文共享与可控性，正好是行业两派争论的一侧，再补「如果做，我会按任务可并行性和上下文隔离去拆」。
不该说：现编「我们也调研过多 Agent 编排」的细节，或反过来贬低多 Agent「没什么用」——前者被追问即穿，后者显得视野窄。

**④ 「平台多少人用？什么规模？」**
应对：如实说内部平台没有对外规模数字，把价值定在链路复杂度（竞态、安全收口、多环境隔离）和具体修复案例上。
不该说：任何估算出来的数字——下一个追问「DAU 多少」就崩，且违反你自己定下的不编造底线。

**⑤ 「现在 15K，凭什么要 28–32K？」**
应对：中性讲事实——入职定薪偏低、涨幅一直受限，期望的是和职责匹配的市场价（前后端+沙箱+部署+权限+可观测一条链），说完立刻拉回职责清单。
不该说：「前公司压我工资」或把薪资当离职动机主线——一个带情绪，一个让 HR 给你贴「给钱就走」的标签。
