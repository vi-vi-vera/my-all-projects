## 一、先做一件事：口径校准（D1 必做，15 分钟）

11-05 的材料修订推翻了旧稿里的 Git 说法。**旧稿背得越熟，被追问时崩得越快。** 练习前先把这两栏对齐。

| 维度 | 设计方案 `git-write`（已实现、未接界面） | 线上现状（两条链路） |
|---|---|---|
| 谁发起 | 模型只能调 `/api/git/agent/write` | ① 面板按钮 → 后端接口；② 模型在沙箱跑原生 git |
| 作用域 | 30 分钟、签名 + 载荷哈希，换仓库/分支签名即失效 | ① 后端按当前用户凭证 + 冲突分叉预检；② 等同于用户仓库权限 |
| 凭证位置 | 模型只拿短期令牌，不接触仓库凭证 | 凭证写在沙箱 `.git/config` 的 remote，写操作前还会补写一次 |
| 执行前检查 | 后端验签 + 预检再执行 | 面板链路有预检；对话链路只靠提示词约束「不要自作主张提交」 |
| 必说的边界句 | 「设计并实现过，但前端工作流只有 chat / deploy-preflight / service-start，没有 git-write 入口」 | 「不能说凭证不进沙箱，也不能说模型不再直接 push」 |

**校准动作**：把 `面试问答合集/待补答案-系统设计.md` 2-1 的「取舍 1」和 11-04 模考 Q5 的「标准答法」逐句过一遍，凡出现「凭证不进沙箱」「载荷里根本没有仓库地址」的，全部改成分栏表述。

**新增的两个追问防线**（材料里原来没有，答出来是加分）：
- 令牌原载荷在 30 分钟内可重放，一次性 nonce 没做；
- 光接 `git-write` 不够，还得撤掉沙箱 remote 里的凭证，否则旁路还在。

## 二、通用事实底稿（每次派活粘贴在最前）

> Agent 读不到你本地文件，必须自带上下文。以下可直接复制。

```text
【背景】
刘奕晨，中国传媒大学软件工程本科（211），5 年经验，深圳。前端出身，2026-03 转全栈。
现为某企业内部 AI 编程平台的两名主力开发之一（与另一同事平级分工），负责沙箱 Git、预览启动与状态、
部署链路、上传与身份、Skills 与 Agent 运行时、会话与协作、监控、前端工作台。
目标岗位：AI 应用 / Agent 全栈，深圳，报价 28–32K，底线 22K。

【2026-11-04 模拟一面：66 / 140】
Q1 自我介绍 11；Q2 架构归属与边界 7；Q3 预览九态与竞态 12；Q4 概念概括 12；
Q5 Git 令牌威胁模型 9；Q6 评估与回归集 13；Q7 系统设计 2。
三个模式：① 讲「做了什么」不讲「为什么这么定」；② 强项答成简历一行字；③ 一开口就说「不清楚」。

【最新事实口径（2026-11-05 按代码核对，必须遵守）】
1. 线上 Git 两条链路：
   - 面板提交推送：按钮 → 后端接口 → 后端取当前用户凭证 → 冲突/分叉预检 → 提交推送。
   - LLM 对话：模型在沙箱跑原生 git；凭证已写进沙箱 .git/config 的 remote，写前补写，所以能 push；
     只靠提示词约束「不要自作主张提交」，不经过面板预检。禁止说「凭证不进沙箱」。
2. git-write 受控令牌：30 分钟、签名 + 载荷哈希，只能调 /api/git/agent/write；前端工作流没有入口
   → 设计并实现过、未接入界面。讲威胁模型时按「设计方案」讲。
3. 部署：deploy-preflight 从模型手写 curl 改为受控 MCP 工具，令牌绑定本次操作（已落地）。
4. 预览：四个异步源（轮询/聊天流/启动流/沙箱阶段）→ 后端综合沙箱存活 + 版本快照 + 启动流致命错误 +
   探两次间隔 1 秒的 LISTEN 检查，输出九态之一 + 原因；前端纯函数合并本地上下文；用「本轮启动时间」
   过滤上一轮迟到失败（不是和当前时间比），更稳是递增 runId。缺文件复现 60s→6s。
5. 沙箱换 OpenSandbox 后 7 个 Git 接口合并为一次往返：状态检查 10+→1，提交推送 6→1。
6. 会话：截断两边都删（DB + 模型侧上下文）；输入队列前后端都做并持久化；历史会话按需迁移约 3507 个。
7. 可观测：AI 调用链接 Langfuse，与伽利略共用 TracerProvider 同 trace_id；OTel v1/v2 Proxy 兼容；
   业务拦截从 ERROR 改为 Abandoned→WARNING；修正 cache token 与成本口径。
8. 迁移：9 服务 / 4 业务线，两人分工，只负责仓库、流水线、配置；DNS/CLB 不是我的。
   QPilot 走 stream CI，未接统一发布审批流（主动说例外）。
9. 没有用户量 / 调用量 / PV 数据，不编。
10. 多 Agent / RAG / 微调没落地；评估只有个人 demo 的 10 条 golden cases。

【不能说过头】
QPilot 不是我创建的；60s→6s 只是缺文件一个场景；Git 收益是往返次数不是耗时；
预热池是空实现、白名单与沙箱代理已删；不写「主导整个平台」。
```

## 四、七张任务卡（可直接复制）

### A · 懂哥 ｜ 每日追问陪练（核心，别省）

- **何时**：D1–D5 每天 20 分钟；D8–D12 抽卡；D13 整场恶面。
- **为什么是它**：14 天计划里的三级判別法本来就是它设计的，它擅长把「好像懂了」逼成「真的懂了」。
- **粘贴材料**：通用事实底稿 + **当天主靶那一段答案原文**（从 `待补答案-*.md` 复制 1–2 页，别整份贴）。
- **任务正文**：

```text
你是面试追问陪练。下面是我的事实底稿和今天的答案原文。
今天的主靶是【填写：自我介绍 / 架构边界 / 九态竞态 / 令牌威胁模型 / 系统设计】。

按三级判别给我追问，不要给我答案，也不要评价我：
- L1 拆结论 2 条：问这个机制到底防谁、为什么是这个值。
- L2 找反例 2 条：反着设、举不管用的场景、同族对比。
- L3 清零重建 1 条：什么条件都不给，从需求一句话开始设计。

要求：
1. 每条追问必须绑定我项目里的具体事实，不许出现「为什么这么设计」这种通用句；
2. 每条必须能逼出取舍或数字；
3. 最后给一句「过」的判据：答到什么程度算这题过了。
输出 ≤600 字，表格即可，不要前言。
```

- **验收**：5 条里至少 3 条是项目专属的；如果它给的是通用句式，直接退回「换成我项目里的具体机制重写」。
- **二次用法（更有价值）**：练完把**录音转文字**贴回去，只问一句「按 L1/L2/L3 判，我挂在哪一层，一句话原因」。这才叫陪练，不然只是出题。

### B · 后端工程师 ｜ 系统设计与威胁模型

- **何时**：D2 首讲 2-1；D4 令牌三层；D5 系统设计定稿；D10 二面前复核。
- **粘贴材料**：通用底稿 + `待补答案-系统设计.md` 全文。
- **任务正文**：

```text
你是二面技术面官（后端架构）。下面是我的系统设计稿和事实底稿。
任务：把 2-1（AI Agent 工作台）和 2-2（Chat + tool call + diff + preview）加固成能抗三层追问的 8 分钟口述骨架。

每题给：
① 七段骨架，每段 ≤2 句：需求澄清 3 问 / 数据模型 / 状态机 / 渲染 / 错误与安全 / 性能与监控 / 取舍 2 个；
② 最可能被追问的 5 个问题 + 每个 30 秒答法；
③ 一句话边界（哪里不是我的、哪里是逐步长出来的）。

另外：按底稿口径重写 Git 令牌威胁模型的三层边界（作用域 / 凭证隔离 / 执行侧兜底），
明确区分「设计方案未接界面」和「线上两条链路的现状」，并给 3 个反例追问和应答。

硬性：不要复述我稿子里的原句，要补我没写的追问；数字只用底稿里的。输出 ≤1500 字。
```

- **验收**：5 个追问里至少 2 个是你完全没想过的；如果全是稿子里已有的，退回重写。
- **注意**：它会顺着你的稿子夸，所以第一句必须明确「不要复述、只补缺口」。

### C · 运维运营 ｜ 工程与生产

- **何时**：D9 一次讲完。
- **粘贴材料**：通用底稿 + `待补答案-工程与生产.md`。
- **任务正文**：

```text
你是 SRE / DevOps 面官。下面是我的工程与生产材料。
任务：把两段真实经历做成可直接口述的排查案例。
案例 A：Langfuse 依赖的 ClickHouse 跨环境连不通（云上到 IDC 被 acl 拦截；白名单 / 复用 / 自建，选了自建）。
案例 B：Langfuse 上线后上报失效（ClickHouse 磁盘被历史数据写满；清数据 + trace 表 1 天 TTL + 100G 专用盘）。

每个案例给：① 5 步排查口述（分层 → 逐层排除 → 定位层 → 临时 vs 长期 → 验证），每步 ≤2 句；
② 3 个追问 + 30 秒答法；③ 一句边界（哪些不是我的）。
再加：被质疑「QPilot 没接审批流是不是不规范」时的 60 秒应答，要讲出取舍和补救条件。

硬性：只讲材料里有的事实，不编监控指标。直接输出文本，不要调用终端或代码执行工具。输出 ≤900 字。
```

- **验收**：案例 B 能不能接在案例 A 后面讲成「自建选择的代价兑现」——接得上说明结构成了，接不上说明还是两个孤立故事。
- **踩坑记录**：这个 agent 会想用代码工具统计字数，会卡在审批。任务里必须写死「不要调用终端/代码工具」。

### D · 前端工程师 ｜ 一面基础关

- **何时**：D6 第一遍、D9 手写题。**AI 线期间只在这两天用。**
- **粘贴材料**：通用底稿 + `待补答案-前端保底线.md`。
- **任务正文**：

```text
你是前端面官，面 AI 应用 / Agent 全栈岗（3–5 年，偏 TS / React / Node）。
任务：给我一份「一面基础关」15 分钟速答包。
1) 12 道高频题（TS 类型与泛型、事件循环与微任务、闭包与内存、React 并发与渲染、hooks 依赖、
   SSE 流式渲染、Node 流与背压、错误边界、跨端通信、请求竞态、大列表、XSS/CSRF），

3) 指出哪 4 题最可能被 AI 岗面试官用来「验真假」——必须能对上我底稿里的真实项目。

硬性：不铺 CS 基础，不长篇。输出 ≤1200 字。
```

- **验收**：12 题里每一题的「坑」都要能连回你的真实项目（九态、截断、上传门禁、凭证边界），连不上的删掉，别背。

### E · 招聘专员 ｜ 阶段验收（D7 / D13）

- **任务正文**：

```text
附件是我的事实底稿和上一场模考记录（66/140）。

1) 评分表：5 维 × 5 分（结论先行 / 机制与数字 / 边界诚实 / 抗追问 / 取舍判断），

3) 通过线：总分、单题下限、必须出现的 3 个信号。

硬性：严格 ≤700 字，只输出表格和短句，不要前言、不要解释、不要复述方法论。
```

- **注意**：这个 agent 输出长了会断流（11-04 那次就是 `IMATE_STREAM_TRUNCATED`）。字数限制不是建议，是硬要求。断了就重发，并把它上一轮的输出删掉再发。

### H · 鹅厂职业经纪人 ｜ 不建议使用

实测两次都以「我不太方便回答这类问题」拒答（一次带薪资博弈措辞，一次改成纯事实陈述，仍然拒）。**定价与终面直接用招聘专家**，职责边界更清楚，也不会拒。

## 六、派活时的六个坑（都是实测踩过的）

1. **Agent 读不到本地文件。** 必须把材料原文贴进对话，或者用客户端的附件功能上传。只给路径它读不到。
2. **一次别超过 3 份材料。** 给多了它会去翻别的文件，3 分钟起步，最后跑偏。
3. **字数上限是硬约束。** 不写字数，招聘类 agent 大概率输出过长被截断。
4. **明确禁止代码工具。** 有些 agent 会用 execute_code 数字数，卡在审批上永远不返回。任务里写死「直接输出文本」。
5. **不要问「我答得怎么样」。** 这类问题只会得到鼓励。要问「挂在哪一层，一句话原因」。
6. **不要在情绪差的时候模考。** 模考日只做模考，不复盘，不复盘完立刻再考。

## 七、每天结束前三条验收（缺一条当天无效）

1. 录音回听，缓冲词（很多 / 大致 / 慢慢 / 就是说）不超过 1 个。
2. 主靶不看材料能讲 60 秒，含 1 个数字 + 1 个取舍。
3. 能自己提出面试官最可能问的下一个问题，并当场答出来。

## 八、14 天里最该守住的三件事

1. **口径一致 > 答得漂亮。** 一个「凭证不进沙箱」说错，前面所有安全相关的分数清零。
2. **机制支撑是唯一能涨的维度。** 结论先行可以靠模板，抗追问可以靠练，但「原做法 → 问题 → 改成什么 → 数字」这四格没有捷径。
3. **投递不能停。** 练到 105 分但没有面试，等于 0。每周 6 个，雷打不动。
