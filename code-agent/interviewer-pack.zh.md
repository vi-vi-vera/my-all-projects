# Code Agent — 面试官题包

> Mode: interviewer · 目标：验证候选人是否真的理解云端 AI 代码生成系统，而不是只会复述“调用大模型”。

## 使用方式

- 建议选 6-8 题，至少覆盖 architecture / security / reliability / trade-off。
- 每题先让候选人讲项目事实，再追问边界和取舍。
- 评分时优先看：是否能画出真实链路、是否知道失败分支、是否能说出为什么这样设计。

## 题目清单

### IQ-01. 为什么要同时提供 `/api/agent/start` 和 `/api/agent/chat`？

**考察点**：异步长任务、SSE、接口复用、响应时机。  
**追问**：如果 `/start` 响应已经发出，后台失败了你怎么通知前端？  
**优秀回答**：能说明两者共享 prepareConversation 和 Orchestrator，只是传输方式不同；能讲 `/start` 通过 `/check` 轮询，异步错误必须落库，不能再写 response。  
**合格回答**：知道一个流式、一个异步，但对后台错误处理讲得浅。  
**不合格回答**：只说“一个同步一个异步”，说不出项目里的 conversation 状态流转。

### IQ-02. Session、Conversation、App 三张核心表分别解决什么问题？

**考察点**：数据建模、任务状态、产物元信息、工作区生命周期。  
**追问**：如果把它们合成一张表，会出现什么维护问题？  
**优秀回答**：能区分 workspace、任务状态、最终产物；能讲 messages、deployments、tool_calls 和级联关系。  
**合格回答**：能说出大致含义，但对多轮和二创场景关联不清。  
**不合格回答**：把 session 当登录态，把 app 当 conversation 的别名。

### IQ-03. 模板严格匹配为什么要先把 prompt 解码成骨架？

**考察点**：结构化输入、hash 索引、占位符替换。  
**追问**：为什么不直接把原始 prompt 做 hash？  
**优秀回答**：能解释图片 URL、列表、头像 JSON 等变量会污染匹配；骨架稳定后可 O(1) 查 hash，命中后用 extractedItems 替换占位符。  
**合格回答**：知道骨架是为了去掉变量，但说不出执行阶段怎么用。  
**不合格回答**：认为模板匹配就是字符串 includes 或关键词匹配。

### IQ-04. trag 模糊召回为什么不能直接命中模板？

**考察点**：向量检索局限、误召回、LLM judge、降级策略。  
**追问**：LLM judge 超时或返回异常时应该怎么处理？  
**优秀回答**：能说明相似度不等于可套模板，模糊候选只进入二次判断；异常降级 miss，避免错误模板上线。  
**合格回答**：知道需要二次确认，但不清楚 need_modify 转 remix。  
**不合格回答**：认为分数高就应该直接复用模板。

### IQ-05. Prompt Guard 在链路中的位置为什么是 strict 之后、fuzzy 之前？

**考察点**：调用成本、安全前置、模板特例。  
**追问**：Guard 关闭时系统怎么处理拦截结果？  
**优秀回答**：能说 strict 便宜且确定，命中模板可快速走；未命中后先 guard，拦截时不再触发 RAG/LLM；观察模式只打 tag 放行。  
**合格回答**：知道 guard 做安全检查，但说不清顺序原因。  
**不合格回答**：认为所有请求都先调用 guard，没有意识到模板快速路径。

### IQ-06. Claude Code 工具权限是怎么控制的？

**考察点**：工具调用安全、路径校验、Bash guard、sandbox。  
**追问**：为什么不能只在 system prompt 里告诉模型不要越权？  
**优秀回答**：能讲 `canUseTool`、Bash 校验、路径必须在 workspace、skills 只读、系统敏感目录 deny read/write。  
**合格回答**：知道有限制，但只停留在“沙箱”。  
**不合格回答**：认为 Claude 自己会遵守 prompt，不需要后端校验。

### IQ-07. OrchestratorService 为什么不直接把所有状态更新和埋点写在主流程里？

**考察点**：事件总线、横切关注点、可观测性解耦。  
**追问**：事件总线会带来什么排查成本？  
**优秀回答**：能说明主流程只做编排，监听器处理状态推进、phase、Langfuse、Galileo、tool calls；也能指出监听链路需要集中注册和文档化。  
**合格回答**：知道“解耦”，但说不出哪些监听器。  
**不合格回答**：把事件总线理解成跨服务消息队列。

### IQ-08. 验证-修复循环如何避免把任务状态卡死？

**考察点**：状态机、CAS、异常兜底、自动修复。  
**追问**：验证失败是否应该阻断部署？  
**优秀回答**：能讲 completed -> validating -> running -> completed 的状态转换，异常时回到 completed，达到最大轮次后记录错误并继续部署兜底。  
**合格回答**：知道会自动修复，但状态流转不清晰。  
**不合格回答**：以为生成完就直接部署，没有验证阶段概念。

### IQ-09. 部署链路为什么要同时保存源码和部署产物？

**考察点**：COS 结构、二创恢复、线上访问、跨环境迁移。  
**追问**：只有 deployments 没有 workspaces，会影响什么能力？  
**优秀回答**：能区分 `workspaces/{appId}` 源码和 `deployments/{appId}` 产物；源码用于 remix、模板复制、重建部署，产物用于线上访问。  
**合格回答**：知道一个是源码一个是部署文件，但场景讲不全。  
**不合格回答**：认为二者重复，可以删一个。

### IQ-10. Remix 二创如何避免覆盖当前工作区？

**考察点**：恢复策略、首次调用、workspace 内容判断。  
**追问**：DB 找不到 app，但 COS 有 workspace，要不要允许继续？  
**优秀回答**：能讲首次二创强制恢复，后续只在 workspace 为空或不可访问时恢复；DB 缺失但 COS 有源码时允许 fallback。  
**合格回答**：知道从 COS 恢复，但不知道何时恢复。  
**不合格回答**：认为每次都覆盖工作区。

### IQ-11. 插件 skills 为什么用软链挂到 workspace？

**考察点**：Claude Code Skill 发现机制、插件隔离、安全。  
**追问**：为什么 `.claude/skills` 不允许写？  
**优秀回答**：能讲插件下载后软链到 `.claude/skills`，Claude Code 通过 Skill 工具发现；只读防止模型修改插件缓存或污染其他任务。  
**合格回答**：知道插件能扩展能力，但不知道 skills 目录机制。  
**不合格回答**：把插件理解成普通 npm 包。

### IQ-12. 取消功能在多实例下有什么边界？

**考察点**：AbortController、进程内 Map、多实例一致性。  
**追问**：如果 cancel 请求打到另一个 pod 怎么办？  
**优秀回答**：能说明本地 Map 只能中断本实例活跃任务；数据库可标 cancelled，但跨实例精准 abort 需要 Redis Pub/Sub 等广播。  
**合格回答**：知道 AbortController，但没指出多实例限制。  
**不合格回答**：认为更新数据库状态就一定能停止 Claude 进程。

### IQ-13. taskMonitor 如何避免误杀其他实例正在跑的任务？

**考察点**：数据库心跳、workspace 心跳、孤儿任务修复。  
**追问**：为什么要同时刷新 `.heartbeat` 文件？  
**优秀回答**：能讲 running conversation 的 updated_at 每 30 秒刷新，修复只处理超过阈值未更新且不在本实例 activeIds 的任务；`.heartbeat` 防止清理服务删目录。  
**合格回答**：知道有心跳，但说不清 DB 和文件两条线。  
**不合格回答**：认为内存 Map 足够判断所有任务。

### IQ-14. Rainbow 配置热更新带来的收益和风险是什么？

**考察点**：远程配置、模型参数、fail-fast、fallback。  
**追问**：哪些配置缺失应该拒绝启动，哪些可以降级？  
**优秀回答**：能讲模型、超时、验证开关、trag 阈值等由配置控制；trag 启用但关键字段缺失应 fail-fast，普通配置缺失可 fallback。  
**合格回答**：知道不用发版就能调参数。  
**不合格回答**：认为所有配置都可以随便为空。

### IQ-15. 模板路径和 Agent 路径如何平衡速度与质量？

**考察点**：确定性分层、成本、质量、误命中。  
**追问**：什么时候你会选择关闭模糊匹配？  
**优秀回答**：能讲 strict 直接模板、fuzzy 只做候选、judge 决定 miss/remix、异常降级 Agent；如果误召回率高或阈值未校准，应先关闭 fuzzy。  
**合格回答**：知道模板快、Agent 灵活。  
**不合格回答**：只追求命中率，不考虑误命中质量损害。
